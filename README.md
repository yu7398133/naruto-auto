> 不会因为今天跑过就被跳过；组内的任务集会所是**常驻挂机**任务（`hangLoop`）——
> 每轮领完/接完就**回主界面等 5 分钟**，再重新拖屏进集会所面板，靠「主界面 ↔ 集会所」来回切换
> 维持活跃（v0.5.81：面板内轻点/短滑保活实测仍被判「无操作」超时）。
> 它排在数组末尾、也不参与分类按钮的「都没勾选→跑全部」兜底 —— 想只跑它就**单独勾选它**再点 `🥊 战斗`。

## 战斗辅助详解

战斗环节是本项目迭代最多、也最容易踩坑的部分。当前实现（v0.5.81）如下：

### 连招节拍

| 动作 | 屏位 | 节奏 |
|------|------|------|
| **普攻** | `k` | **一直按住不放**（`battle.holdAttack`），按住期间照常轮询其他技能 |
| 技能 1 / 技能 2 | `j` / `i` | 0.5s 高频补点（`ASSIST.jiFast`） |
| 替身 | `space` | 0.4s「秒替」（`ASSIST.sub`） |
| 大招 / 密卷 / 通灵 | `o` / `e` / `r` | 5s 轮询组（`ASSIST.burst`），组内间隔 120ms |
| 左右朝向 | `a` / `d` | 进场 15s 起交替点击，之后每 15s 一次 |

**为什么技能要「补点」而不是「按住」**：云游戏鼠标通道是单指针模型，无法同时按住多个位置（0.5.59 实测确认）。所以只有普攻真正按住，技能 1/2 用高频补点近似「持续按」的手感。

**为什么普攻要每拍重建按压态**：单指针模型下，任何一次其他位置的点击都会把按压点挤走——替身 0.4s 秒替一跑，按住立刻失效（实测帧差从 25~41 跌回 2~9）。因此 `combatStep()` 每拍末尾都会 `_reassertHold()` 静默做一次 release+down，把按压态抢回来。

### 结算识别

战败局是早期最大的盲点：原金色横幅探针只认胜局，败局只能等超时。现在用**胜负双探针 + 黑屏序列**：

- `victoryBanner`：胜利「胜」字主体，金色（约 200,202,81），tol 45
- `defeatBanner`：失败「失败」大字主体，紫灰（约 79,83,107），**tol 25**
- 两者同归 `SCENE.BATTLE_END`；`detect()` 返回值新增 `byProbe` 字段，日志会区分「胜负已分 / 失败」
- 战斗结束后出现黑屏再进结算，用「黑屏 → 结算」的变化序列提高识别准确率

> 调 tol 的教训：tol 放到 40 时，胜局录制里有 9 个暗色帧会误命中失败探针，必须收紧到 25。

### 角斗场

- 默认循环 **15 局**，`arenaBattleRounds` 可在面板「🥊 战斗」组尾部直接输入
- 重复战斗**不回主界面**：v0.5.78 起靠 `waitForEnd` 的**观察窗**判断「自动续局 vs 真打完」——识别到「胜负已分」横幅后不立刻返回，而是开一个 6s 观察窗：黑屏过场后画面重新动起来 = 游戏自动续了下一小局，**立刻接着连招**（不出任务层、不空窗）；窗口到期画面仍不动才判本局结束，下一轮点「选对手 → 开始对战」
- 忍术对战专用结算参数（v0.5.78）：金色横幅**单拍强命中**即落判（横幅只显示 0.3~1s，等连续 3 拍必漏）、屏蔽在登场画面必误报的「失败」探针、开局 40s 内不许用「画面静止」判结束（登场画面会静止 4.5s+）、静止需连续 8 拍（≈2.4s）、单场连招上限 300s
- **一步一自检 + 解卡（v0.5.79）**：一局打完游戏会连弹「战斗结果 → 黑屏 → 奖励 → 任务/奖励面板」一串页面，脚本不再对着固定两点盲点 —— 每一下都量「点完画面变没变」，**没反应就判「不在这界面上」**，逐个试点候选「确定/关闭/返回」解卡（哪个让画面动了用哪个），全都不动就回主界面重进；「选对手/挑战」连续 5 次点不动即停手告警，绝不在陌生页面乱点
- **连续静止 20s 兜底结束（v0.5.79）**：画面像素级冻结 ≥20s 即判「已不在战斗中」结束本场 —— 修掉「开局就落在静止陌生页面上时，`battleStarted` 闸把『静止=打完』这条唯一出口永久关掉、只能盲点到 6 分钟超时」的老问题（实测 21.7 分钟只打完 5 局 → 修复后约 2.5 分钟）
- **黑屏过场期间绝不点击（v0.5.79）**：`scene=loading`（全屏亮度 <12）时松开按住并停手 —— 之前的追加点击正是「点开战后面板」的元凶
- **全屏黑过场 = 整场结束（v0.5.81）**：新增 `darkEndAfterMs`（角斗场传 25s 时间闸）。实测亮度三档分得很开 —— 战斗中最低 **BR 100+**、「小局切换」暗帧 **14.0~22.3**（不是全屏黑）、「整场结束」暗帧 **1.3~5.3**（= `SCENE.LOADING`）。命中即 `return 'darkend'`，放在所有闸之前。旧实现只在 `scene=BATTLE_END` 时才用黑屏做序列确认，而黑屏后画面停在结算/面板页 → 判不出 BATTLE_END → 整条路走空，只能等 20s 静止兜底。回放验证：6:47.30（22.3）/ 7:06.23（14.0）不判，**7:33.33（5.3）精确落判**
- **「点得动吗」的判据收紧到 0.05（v0.5.81）**：卡在战后页面时画面自身就有 0.010~0.015 的轻微动画，用默认阈值 0.012 会把盲点判成「点到了」→ 脚本以为选对手/开始对战生效、一路盲点。实测：无效 0.0149/0.0104/0.0107 vs 有效 0.5676/0.3220 → `REACT = max(THR×3, 0.05)`，两侧余量 3.4 倍 / 6.4 倍
- **战后不是靠横幅收尾就直接回主界面重进（v0.5.81）**：`darkend / frozen / timeout` 三种结束原因下不再让下一轮去猜页面、也不再逐个试 8 个解卡落点（那些点击本身可能在面板上乱点）——先 `goHome()` 再重新进场
- 单任务超时 5400s（90 分钟）

### 任务集会所

- 从**日常**移到 **🥊 战斗**组，物理排在 `TASK_DEFS` **最末**（8 小时常驻循环排在中途会把秘境/角斗场饿死）；标注 `hangLoop`，不参与「跑全部」兜底，要单独勾选
- 只接**红宝箱 / 蓝宝箱**任务（绿的不做），同时最多 3 个（= 顶部槽位数）；**不用「换一组」**（刷新额度不免费）
- **空闲 / 满 3 只认顶部 3 个槽位**：逐槽判 空缺 / 计时中 / 可领取，空闲位 = 可领取 + 空缺，三槽全计时中才算满 3
  - ❌ 不读底部「可接受任务: N/9」—— 该计数在任务完成那一刻就归还（三槽全「可领取」时它仍显示 9/9）
  - ⚠ 宝箱 = 该行**最右侧**奖励格（行内奖励项 1~4 格不定，绝不能固定取第 3 格）
- **进面板路径（v0.5.80 按真机录制校准）**：回主界面 → 两段拖动 `(325,282)→(1117,282)` / `(301,282)→(1017,282)` → 点入口 `(545,466)`
  - 拖动高度取录制实测的 **282**（0.5.75~0.79 误写成 360：(301,360) 压在 UI 元素上、图像 std≈31.7，起拖容易被当成点击吞掉；(301,282) 是纯色远景、std≈3.9）
  - 首轮没打开面板 → 回主界面后用旧高度 360 重拖一次 + 备用落点 `(591,480)`
- **面板判据（v0.5.80 收紧）**：只认「**接取按钮金色 ≥2 行**」（实测 面板 3 / 主场景 0 / 推荐小队页 0 / 出发页 0）
  - ⚠ 右下「换一组」金色**不是面板独有** —— 推荐小队页 (212,181,78)、出发页 (207,174,73) 同位置也是金色；旧判据 `hangOk || btnOk>=2` 会把这两页当成面板 → 之后的领取/保活就在那两页上乱点
  - 按钮全灰（任务被接完）时用「可领取」标签模板复核兜底（该标签面板独有：面板 SAD 11.6 命中 / 主场景 48~52 / 推荐小队页 63~107 / 出发页 63~89，阈值 25）
- **槽位光晕兜底带量程上限**（`MISSION_GLOW_V_MAX = 80`）：光晕只在面板内有区分度（56.8~74.4）；非面板页 86~228 会把 3 个槽位全判「可领取」
- **接任务三步**（与真机录制完全一致）：点该行接取 `(1173, 285/398/510)` → 推荐小队 `(936,580)` → 出发 `(1172,627)`
- **挂机方式（v0.5.81 换掉）**：每轮领完/接完就 **回主界面 → 等 5 分钟（`MISSION.pollMin`）→ 重新拖屏进面板**，靠「主界面 ↔ 集会所」来回切换保持活跃
  - ❌ 旧做法（0.5.77~0.80）是留在面板里挂机、每 3 分钟轻点面板空白 / 单向短滑 —— 用户实测「**还是被判定为无操作而超时**」（`keepAliveMin` / `keepAlive` / `sleepInPanel` 保留但不再调用）
  - ⚠ 等待期间刻意**不做任何操作**：主界面上的拖动会移动镜头，下一轮 `openPanel` 的两段拖屏坐标（325→1117 / 301→1017）就会偏、反而进不去面板
- 单任务超时 8h + 5min

### 安全闸

1. **连招总时长上限**（`battle.assistMaxMs`，默认 150s；**角斗场按场覆盖为 300s**）：战斗再久也不无限连点，防止战斗其实早已结束、辅助还在盲点把当前界面的按钮点开
2. **静止/超时/结算/stop 一律 `releaseHold()`**：不会把普攻按住状态带到结算或主界面

## 视觉识别

脚本用三种手段识别画面，按可靠性递进：

| 手段 | 用途 | 实现 |
|------|------|------|
| **颜色探针** | UI 定位（按钮、横幅、面板） | 区域平均色 + 曼哈顿距离容差 + 亮度标准差下限防纯色误判 |
| **SAD 模板匹配** | 文字/图标（如「普通招募」页签） | `Vision.findTemplate`，灰度 SAD 均值，阈值 25 |
| **白字行聚类** | 模板失效时的兜底 | `Vision.findTextRows`：grayMin 170 / satMax 60 / gap 8 / minCount 3 |

> **分辨率教训**：云端可能把 720p 重采样成 1080p 推流，抗锯齿变化会让 720p 时代抠的模板失准——「普通招募」页签 SAD 从 0 涨到 28.7，卡死在阈值 25 上（位置完全正确却判未命中）。修法是①按现场 1080p 帧重抠模板，②加 `findTextRows` 第二路径。**新增模板时务必在当前流分辨率下抠图。**

### 视觉探针（PROBES）

`PROBES` 对象集中存放所有 UI 颜色指纹：

```js
{
  area:   [x1, y1, x2, y2],   // 1280×720 逻辑空间
  color:  { r, g, b },        // 区域平均色
  tol:    35,                 // 颜色容差 (曼哈顿距离)
  minStd: 0..15,              // 区域亮度标准差下限 (防纯色背景误判)
  click:  [x, y],             // 命中后点击这个点（可选）
  label:  '中文名',
  verified: true/false,       // 是否来自上游实测标定
}
```

### 核心模块

| 模块 | 职责 |
|------|------|
| `Config` | GM_setValue / localStorage 持久化，深合并；版本升级自动补字段 |
| `Store` | GM_* 与 localStorage 双通道，注入环境无油猴也能跑 |
| `Progress` | 每日/每周成功记录，配合 `runtime.skipDoneToday` |
| `Runtime` | 全局中止信号，stop() 一秒内打断所有 sleep |
| `SdkAdapter` | 三组能力检测（Oprate / arm / legacy）；事件载荷多格式 + DOM 派发兜底；clientX/Y 视口坐标 |

| `TaskScheduler` | 队列 / 重试 / 超时 / 事件 / 停止 / 每日去重 |
| `ControlPanel` | 拖拽面板、状态徽章、预览取色、设置面板、任务列表 |
| `NarutoAuto` | 主入口：异步检测 SDK，画面元素看门狗 |

## 坐标系统

所有坐标基于 **1280×720** 基准分辨率定义，运行时按视频元素真实尺寸（`videoWidth × videoHeight`）自动换算。

| 组 | 数据来源 | 可信度 |
|---|---------|-------|
| `COORDS.nav` | 实测标定 | ✅ 实战可用 |
| `COORDS.common.close` | 通用规则 | ✅ 已被 minStd 加固 |
| `COORDS.common.back` | 估算 | ⚠ 需校准 |
| `COORDS.collect / daily / weekly / battle` | 逐个录制校准 | ✅ 主要流程已校准 |
| `BattleFlow.PLACES` | 校准 JSON（a d 空格 j k i o e r 九个屏位） | ✅ 实战可用 |

> 注意：战斗里的 `j` / `i` / `k` 等是**屏幕位置**（按钮坐标），不是键盘按键——2026-09-13 起战斗辅助全部走位置点击，因为部分云游戏实例的键盘通道不可靠。

校准方式（任选其一）：

- **🎓 校准模式（推荐）**：面板「🎓 校准」或 `Ctrl+Shift+C` 开启 → 手动把任务做一遍（**点击和屏幕位置都会记录**，长按会记时长）→ Esc 结束 →「💾 导出」。生成的 `COORDS.calib` + `COORDS.calibFlow` 直接可用
  - 「▶ 回放」或 `Ctrl+Shift+P`：把录的序列重放一遍验证（回放中再按一次停止）
  - 「✏ 命名」：给每步起个有意义的名字，支持点号分组（如 `nav.store` → 导出为 `COORDS.nav.store`）；「📃 列表」打印当前步骤
  - 要录 Esc 键本身用 `Ctrl+Shift+E`（单独按 Esc 是结束校准）
- 控制面板「点击预览取色」：鼠标点预览图，自动生成探针代码片段
- `tools/vision-lab.html`：拖入离线截图批量标定

### 🔬 自动运行追踪器（定位自动运行问题）

当自动运行「跑偏了 / 卡住了 / 点了不该点的」却不知道卡在哪一步时，用追踪器把全过程录下来逐帧核对。

- 开启：面板「🔬 追踪」按钮，或快捷键 `Ctrl+Shift+T`（再按一次关闭）。
- 运行中：脚本**每次真实点击 / 滑动 / 按键**都会被记录，每步存档：
  - 逻辑坐标（1280×720）与步骤说明；
  - **当前场景**（脚本当时判定自己在哪）、**命中的探针**（含色距 d，可直接看出「为什么它以为这是结算页」）；
  - **点击瞬间的画面缩略帧**（320×180 JPEG）。
- 长时间录制：环形缓冲上限 2000 步（超出丢最旧），每步仅存缩略帧，几千步也只占几十 MB。
- 导出核对：点「💾 导出」→ 生成**自包含 HTML**（内嵌全部帧）→ 双击打开即可「上一步/下一步/自动播放/跳步」，右侧列表点任一步直达，一眼看出「第几步、以为在哪个场景、点了哪、命中了哪些探针」。

控制台 API：`__narutoAuto.trace.on()/off()/toggle()/state()/count()/dump()/clear()/download()/downloadViewer()`。

> 把导出的 HTML（或 JSON）发开发者，即可精确定位问题步骤，无需反复描述现象。

## 配置说明

配置通过 Tampermonkey 的 `GM_setValue` 持久化，注入场景回退到 `localStorage`。

| 路径 | 说明 | 默认 |
|------|------|------|
| `delay.click.min/max` | 单次点击后等待（**每步兜底 ≥1s**，硬下限 `MIN_STEP_DELAY`/`MIN_OP_DELAY`） | 1000-1500ms |
| `delay.pageLoad.min/max` | 页面切换等待 | 1800-3200ms |
| `delay.short.min/max` | 短动作后等待（盲按返回、结算点击等） | 1000-1100ms |
| `delay.popup.min/max` | 弹窗点击后等待 | 1000-1400ms |
| `battle.minWait/maxWait` | 战斗最短/最长等待 | 15s / 180s |
| `battle.autoBattle` | 进入战斗后开自动 | ✅ |
| `battle.speedUp` | 开倍速 | ✅ |
| `battle.keyAssist` | 战斗连招辅助 | ✅ |
| `battle.holdAttack` | 普攻持续按住（关闭则退回点击） | ✅ |
| `battle.assistMaxMs` | 单场连招点击上限 | 150000 |
| `battle.postRounds` | 结算循环轮数 | 8 |
| `arenaBattleRounds` | 角斗场循环局数 | 15 |
| `vision.enabled` | 启用视觉检测 | ✅ |
| `vision.diffThreshold` | 帧差异阈值 | 0.012 |
| `vision.stableFrames` | 连续静止帧数 | 3 |
| `vision.preview` | 显示预览 | ✅ |
| `nav.requireHome` | 每个任务前回主界面 | ✅ |
| `runtime.taskTimeout` | 单任务超时 | 240s |
| `runtime.skipDoneToday` | 跳过当日已成功的任务（**战斗组除外**，长期任务不记录） | ✅ |
| `runtime.dailyResetHour` | 每日重置点 | 5 |
| `runtime.stopHotkey` | `Ctrl+Shift+Q` 紧急停止 | ✅ |
| `input.mode` | stream / dom | stream |
| `input.jitter` | 点击随机偏移 | 4px |
| `taskSwitches.*` | 各任务开关 | 大部分开启 |

## 控制台快捷 API

```js
__narutoAuto.probe()              // 探测场景（详细输出每个探针的距离）
__narutoAuto.diag()               // 一键自检（SDK/画面/场景/坐标映射），自动复制 JSON 到剪贴板
__narutoAuto.show()               // 展开面板
__narutoAuto.hide()               // 收起为悬浮球
__narutoAuto.toggle()             // 切换面板显隐
__narutoAuto.operator.click(x,y)  // 单点
__narutoAuto.scenes.current       // 当前场景
__narutoAuto.runtime              // 中止信号（接管调试时如遇「已中止」先 runtime.reset()）
__narutoAuto.vision.status()      // 画面状态：ok / no-element / not-ready / tainted
__narutoAuto.vision.saveSnapshot()// 下载当前帧 PNG
__narutoAuto.tasks                // 所有任务定义
__narutoAuto.probes               // 所有探针
__narutoAuto.coords               // 坐标表（唯一的坐标来源，1280x720 逻辑空间）
__narutoAuto.calib.code()         // 导出校准代码（按命名点号分组）
__narutoAuto.calib.rename(1,'nav.store')  // 给第 1 步改名
__narutoAuto.calib.renameAll('nav')       // 批量改名成 nav.1 / nav.2 …
__narutoAuto.calib.list()                 // 列出全部步骤
```

> 悬浮球快捷键：`Ctrl+Shift+A` 切换面板显隐；`Ctrl+Shift+Q` 紧急停止。双击悬浮球直接跑全部已启用任务。
