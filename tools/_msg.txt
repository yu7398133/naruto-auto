v0.6.63: 修复超时任务的「僵尸代码」污染后续任务（Promise.race 不取消输的一方）

根因：
_runWithRetry 用 Utils.withTimeout(task.run(ctx), timeout, task.name) 包任务，
而 withTimeout 是 `Promise.race([task, 超时])` —— **超时只结束「等待」，
并不取消输的那一方**。task.run(ctx) 的 promise 仍在后台继续跑，
还在调 ctx.go()/replaySeq()/ctx.home()，照样往同一个画面点。

实测证据（2026-10-13 日志，秘境挑战 timeout=600000ms）：
秘境探不到准备界面 → 每 ~88s 一轮「回主界面 → 重导航」，10 分钟后被
withTimeout 判超时、调度器 continue 去跑下一个任务，但秘境 run() 没死：

  10:37:47 ⚠ 未探测到「秘境准备界面」图标（等满 20193ms）  ← 这时前台是「特权商店」
  10:37:50 ▶ 免费招募 开始
  10:37:59 🔎 普通招募 score=41.1 ✗
  10:38:06 ⚠ [不在准备界面→重导航] 没看到右上角红叉（dist=67）  ← 秘境僵尸插进来
  10:38:10 ⚠ 未能定位「普通招募」页签 → 跳过本任务
  10:38:10 ✗ 免费招募: 未完成（4 个步骤未达成）

  10:38:47 ⚠ 未探测到「秘境准备界面」图标  ← 这时前台是「角斗场」，刚打开奖励面板
  10:38:52 🎁 奖励状态：第1个红=0%(未领) 第2个红=0%(未领)   ← 一点没领到
  10:39:17 🎁 ⚠ 点了 3 次仍未确认退出奖励面板
  10:39:20 ✗ 角斗场忍术对战: 未完成（1 个步骤未达成）

受害者：免费招募（左侧菜单被僵尸的 ctx.home() 冲掉，普通招募页签 3 次定位失败）、
角斗场忍术对战（奖励一个没领到 + 奖励面板退不出去）。

修复：引入「任务代次（epoch）」——超时检测之外的**取消**机制。
  · Runtime.nextEpoch/currentEpoch/_deadEpochs + newEpoch()/retireEpoch()/
    isEpochDead()/assertEpoch()
  · TaskContext 增加 this.epoch（0 = 非任务上下文 ⇒ 放行）
  · _epochGate() 接在**所有会操作画面的入口**：tap / drag / home / fight / replaySeq
  · Runner._runWithRetry：每次尝试 newEpoch() 并写入 ctx.epoch；
    finally 里 retireEpoch()（成功/超时/异常/重试四条路径都作废）
  · 代次已作废 ⇒ 抛 AbortError 停手（不是静默 return），日志可追

设计取舍：用「作废集合」而非「比较大小」——任务是可能重试（同任务多代次）、
未来若改并发调度的，比较大小会误伤；只有「我被明确作废了」才是可靠信号。
作废集合上限 200（超出淘汰最老的），防无界增长。

新增：tools/test-epoch.js（确定性验证：僵尸被拦 / 有效代次放行 / 代次 0 放行）
